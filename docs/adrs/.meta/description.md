# adrs

**Purpose:** Architecture decision records for features built through the etc harness, from 2026-10-10 on: one short file per decision, grouped by the etc feature of a spec in `spec/` (the README says records are written by `/architect` or by hand). Decisions made before 2026-10-10 stay in `docs/DESIGN.md` and are not back-filled here (`README.md`).

## Key Components
- `README.md` - 8 lines. States the convention (one file per decision, `NNN-slug.md`, numbered in the order decided, with Context, Decision and Consequences; written by `/architect` or by hand) and points to `docs/DESIGN.md` and `ARCHITECTURE.md` for earlier decisions and the ratified rules.
- `F-2026-10-10-markets-that-bite-001` to `-004` - spec 008 (`spec/markets-that-bite.md`): 001 running cost per ore, chosen from observed output; 002 mine margin is one sim function (`sim::mineDailyMargin`, `sim::mineBreakEvenPrice`) and only the losing-days counter is saved; 003 bite is gated and mean price reported; 004 as-built amendments to 002 and 003 (the runner does not call the margin function, `kGolden` did not move and `kGoldenPlayed` was added, a 180-second timeout, what "idled" means).
- `F-2026-10-11-mine-economics-001` to `-004` - spec 009 (`spec/mine-economics.md`): 001 a mine has a size and its depth is derived from tonnes dug; 002 `EnlargeMine` and `CloseMine` orders, an enlargement as fields on the mine; 003 `sim::projectMine`, a pure whole-life projection the AI calls; 004 rules land with neutral data first and gates run on two seed ranges. Spec 009 is folded into spec 010 (step 3) and not built on its own, so these describe no built code yet.
- `F-2026-10-11-first-slice-race-for-the-program-001` to `-004` - spec 010 (`spec/race-for-the-program.md`): 001 the program is company state and the sim decides when the game has ended (`sim/include/sim/program.h`, `sim/src/program.cpp`, `Session::gameOver`); 002 stage research is ordinary research in `data/techs.json` with a program prerequisite; 003 products are resources and a plant is a new entity (step 2, not built; to be re-read with the owner after the step 1 playtest); 004 the slice is built in four playable steps with the owner's playtest gating step 2.

## Dependencies
- Records cite their spec's requirements (`BR-NNN`; six of the twelve) and rule R-001 of `ARCHITECTURE.md`, the sim as the only authority (three: markets-that-bite 002, mine-economics 003, first-slice-race-for-the-program 001).
- The architectural summary for each built feature is in `docs/DESIGN.md` ("Markets that bite (spec 008)", "The race for the program (spec 010, step 1)"), which lists the record range; spec 008's Decisions in `spec/markets-that-bite.md` point to record 004.
- Records name the code and data they govern (`sim/src/mines.cpp`, `sim_runner/main.cpp`, `sim_runner/CMakeLists.txt`, `tests/determinism_test.cpp`, `data/resources.json`, `data/balance.json`, `data/techs.json`, `data/program.json`, `data/ai.json`); no code, test or CI job reads this directory.
- The designs and gray-area notes behind them are in the untracked `.etc_sdlc/features/active/<feature>/`.

## Patterns
- File name `F-<date>-<feature>-NNN-<slug>.md`, where `F-<date>-<feature>` is the etc feature id (`F-2026-10-10-markets-that-bite`, `F-2026-10-11-mine-economics`, `F-2026-10-11-first-slice-race-for-the-program`); title `# ADR-F-<date>-<feature>-NNN: <decision>`.
- Body: `**Date:**`, `**Status:**` (all twelve are Accepted), then one paragraph each of `**Context:**`, `**Decision:**` and `**Consequences:**` (record 004 of markets-that-bite uses a numbered list in its Decision). Each file is 7 lines except that one (12).
- Accepted records are not edited: a correction is a new record that amends the earlier ones and names them, as markets-that-bite 004 does for 002 and 003.

## Constraints
- The actual naming differs from `README.md`'s `NNN-slug.md`: numbering restarts at 001 for each feature (three sequences of 001 to 004) inside an etc feature-id prefix, not one running sequence across the directory. `README.md` has not been updated to say so.
- `spec/race-for-the-program.md` ("Open after step 1") notes that markets-that-bite 003 is superseded in effect for gating by spec 010 and that no amending record has been written; whether one is written is left to the architect.
- Decisions before 2026-10-10 are only in `docs/DESIGN.md`; the ratified rules are only in `ARCHITECTURE.md`, which is generated by `.claude/scripts/baseline.py` and not edited by hand.
