# tests

**Purpose:** The project's unit and integration test suite: one Catch2 v3 executable, `sim_tests`, that exercises the deterministic simulation core (`sim/`), the JSON content loader (`content/`) and the headless game session layer (`game/session/`). It also holds three guard tests that read repository files (shipped `data/`, a sim source file, generated UI tokens, the prose draft) instead of calling code.

## Key Components

Build and shared fixtures:
- `CMakeLists.txt` - defines the single target `sim_tests` from the 26 `*_test.cpp` files, links it, bakes in `DC_DATA_DIR` and `DC_SOURCE_DIR`, and registers every test case with CTest through `catch_discover_tests`.
- `test_content.h` - `test::makeContent()` builds a complete `sim::Content` in code (3 resources iron/copper/lithium, each with its own `mineOpexPerDay`; 5 techs, `survey` and `lithium_processing` plus the program stage projects `program_stage_1..3` requiring stages 0/1/2; 2 regions `north`/`flats`; 1 event `boom`; a small program with deadline day 10,800 and three stages costing 1M/2M/3M that need 1,000 t iron, then 2,000 t iron and 200 t copper, then 3,000 t iron and 50 t lithium; full balance knobs including the spec 008 market clamps and losing-mine notice knobs; full AI knobs including the spec 010 program knobs); `test::setup()` returns a `sim::GameSetup` with one player and one AI named "Rival". Deliberately independent of `data/*.json`.
- `test_strings.h` - prose-catalogue helpers: `test::readTextFile`, `test::fixtureStrings(eventIds, techIds)` (the shipped `data/strings.json` with its `event.*`/`tech.*` keys rebuilt for fixture ids) and `test::addStrings(content)` (copies the shipped strings into fixture content).

Numeric and utility primitives (`sim/`):
- `fixed_test.cpp` - `sim/fixed.h`: `Fixed` construction, truncating multiply/divide, 128-bit intermediates, `compareProducts`, `checkedMulDiv`, `fromDouble` rounding, decimal text.
- `math_test.cpp` - `sim/math.h`: `fixedLn`, `fixedExp`, `fixedPow` against known values, inverse and monotonicity properties, `clampFixed`.
- `money_test.cpp` - `sim/money.h`: `Money` arithmetic, scaling by `Fixed`, ratios, decimal text.
- `ids_test.cpp` - `sim/ids.h`: `StrongId` default-invalid, index wrapping, comparison, tag type distinctness.
- `rng_test.cpp` - `sim/rng.h`: `Pcg32` against the reference sequence, `below` bounds, stream divergence, state restore.
- `random_test.cpp` - `sim/random.h`: `uniformFixed`, `uniformInt`, `approxNormal` distribution checks, deterministic independent `RngStreams`.
- `archive_test.cpp` - `sim/archive.h`, `sim/serialize.h`, `sim/hash.h`, `sim/save.h`: byte layout (little-endian, uint32 length prefixes), FNV-1a hash, truncated/oversized/huge-length rejection, exact save/load round trip, a save holding one queued command of any kind loads, command vectors bounded by the smallest command, rejection of bad headers, inconsistent worlds and saves made with different content.

Simulation rules (`sim/`, each drives `sim::Simulation` through commands and inspects `sim/world_state.h` and `sim/view.h`):
- `determinism_test.cpp` - `sim/simulation.h`: same seed gives the same state hash, different seeds differ, and three golden hashes for seed 42 on fixture content: `kGolden` (one year, nobody gives an order), `kGoldenPlayed` (three years with `sim::HeuristicController` giving both companies' orders, so land, surveys, mines, loans and research are in the state; re-hashed after save/load) and `kGoldenRace` (a race world loaded with stock and cash, both companies racing by rote with `DeliverToProgram`, `StartResearch` and `CompleteProgramStage` until the player founds the program and the rival is a lesser partner; checks stage days, outcome and public notices, re-hashes after save/load, and checks a finished world does not change on another tick).
- `worldgen_test.cpp` - `sim/worldgen.h`: region classification by mineability, deposit caps, opening hand and listing queue promises, plot creation order, deposit presence and log-normal size statistics, per-seed determinism.
- `plot_market_test.cpp` - `sim/plot_market.h` (land auctions, tag `[market]`): listings, relisting and ask decay, bid validation and cash reservation, winner selection, public sales record, withdrawal and cooldown of unsold plots, per-viewer filtering of views and reports, save/load mid-auction; also subclasses `sim::Controller` to test `collectCommands`.
- `markets_test.cpp` - `sim/markets.h` (ore commodity prices, tag `[markets]`): base price and history, power-law equilibrium, sale price impact, sell command validation, demand noise bounds, demand growth, save/load validation, the demand-over-supply and demand-factor clamps read from content (spec 008) and those values in the content fingerprint.
- `sell_policy_test.cpp` - standing sell policies and the month-end cover-costs rule (spec 001) via `sim::SetSellPolicy` in `sim/commands.h`; defaults from the balance data, reserve handling, locked ore, monthly summary, command and save validation.
- `surveys_test.cpp` - `sim/surveys.h`: survey cost and delay, command validation, unbiased log-space noise, "major" estimate flag, save validation, no leakage to other companies.
- `mines_test.cpp` - `sim/mines.h`: capex and build delay, extraction/opex/decline/depletion, mothballing, locked resources, accounting conservation, empty-plot and locked-only notices, survey estimate in the mine view, running-low warnings, save/load; per-ore running cost (the dearer ore of a two-ore mine, mothball share, research and event multipliers), mine margin and break-even with saturation (spec 008), consecutive losing days and the once-per-episode losing-mine notice, its minimum loss share and re-arm run (spec 010, BR-014), and save rejection of impossible losing-day fields.
- `finance_test.cpp` - `sim/finance.h`: loans (capacity, cap on active loans, early repayment), storage charges, insolvency warnings, grace period, bankruptcy effects, save/load validation; also program state and the world outcome surviving save/load and the hash, and saves with impossible program state or outcome being rejected (`[finance][spec010][save]`).
- `research_test.cpp` - `sim/research.h`: research cost and completion, command validation, effect on survey noise and resource unlocks, unlock news, view progress toward locked resources, save validation; a stage project that cannot start before its program stage, the public announcement of stage research, and the view's per-project open flag (`[open]`).
- `events_test.cpp` - `sim/events.h`: event start/duration/end, multipliers on demand, opex and land prices, minimum year and firing rate, order independence, save validation.
- `ai_test.cpp` - `sim/ai_controller.h`: twenty-year run without rejected commands, determinism from a save, AI knobs in the content fingerprint, supply discount, bid jitter fairness, first-mine terms, bankruptcy stop, joint affordability of daily commands; the view's per-ore running cost, margin and break-even and the AI idling, reopening and valuing prospects on them (spec 008); the race (spec 010): delivering what a stage needs and selling the rest, the reserve share and standing sell orders, selling under cash pressure, saving for and starting stage projects, heading for research that unlocks a needed ore, weighting land with a needed ore, completing a stage the day it is ready, and no orders once the game has ended.
- `program_test.cpp` - `sim/program.h` (spec 010): delivery and stage-completion rules called directly (rejection reasons, exact fill, cost charged once, all three stages in turn, progress as the mean delivered share), the program's notices and reject reasons; the endings played through a `sim::Simulation` (founding ends the game, nothing runs after the founding order, rival founding gives lesser partner or lost, the deadline ends the game with everyone lost, bankrupt companies, same-day finishes, a last stage on the deadline day, a finished world refusing every order and not changing under AI hosts); the race in both companies' views; per-company stage days; and save rejection of impossible stage days, completed stages without their research, and founding or deadline outcomes the world does not show.

Content loader and shipped data (`content/`):
- `content_test.cpp` - `content/loader.h` via `content::loadFromStrings` on in-file JSON sources: successful load, and error reporting with paths for bad JSON, unknown/missing keys, wrong types, precision, references, duplicate ids, prerequisite cycles, effect fields, balance and AI knob bounds; all errors collected in one pass. Also each ore's `mine_opex_per_day` and refusal of the old single balance figure, market clamps, losing-mine notice knobs, a project's required program stage, the AI program knobs, and `program.json` (exactly three stages, deadline bounds, positive costs and tonnes, known goods and projects, each stage's project requiring exactly the stages before it, lithium in the third stage, the whole program in the fingerprint, the fixture's program being loadable).
- `data_files_test.cpp` - `content::loadFromDirectory(DC_DATA_DIR)`: the shipped `data/` files load cleanly, specific shipped balance relationships hold (the three program stage projects with their measured costs and durations, the program's day-10,800 deadline and stages, ore break-even shares, one mine moving its own price by at most six percent, iron earning the least per mine, the tuned AI knobs), and worlds generated from shipped data give every one of 200 seeds a fair opening hand.
- `strings_test.cpp` - prose catalogue (spec 002) through `game/format.h` and `content/loader.h`: placeholder filling, plurals, coverage of every notice kind and reject reason in shipped prose, program and mine notice wording, text for the race strip, Program tab and end screen, loader rejection of a broken catalogue, fingerprint behaviour, and key/placeholder parity between `tools/prose/draft.tsv` and `data/strings.json`.

Game session layer (`game/session/`):
- `session_test.cpp` - `game/session.h`, `game/format.h`, `game/trace.h`: money/day/tonnage formatting (including exact prices) and strict parsers, clock advance at speed, player command binding and log, pending orders that wait in the session, can be cancelled, are saved and are summed as committed cash (spec 007), rivals, save/load, stop on bankruptcy, auto-pause rules and their text round trip (including the losing-mine and rival-program stop rules), stopping and refusing orders once the game is over and reporting the sim's outcome, log filtering of relists and unlocks, monthly sales log line, and playtest 4 log wording (`[playtest4]`).
- `trace_test.cpp` - `game/trace.h`, `game/replay.h`, `game/png.h`: every command through trace JSON, queued and cancelled orders and the day an order was given, the program's orders, the end record carrying the outcome, malformed record rejection, replay reproducing a game (including one played to its end), stop-at-day and divergence reporting, replay through a load record, and the PNG encoder checked with an in-test stored-deflate reader.

Repository guard tests (no project headers included):
- `view_source_test.cpp` - reads `sim/src/view.cpp` and fails if it contains `hidden`, `Hidden` or `DepositTruth`.
- `design_tokens_test.cpp` - reads `docs/design/tokens.css` and `game/assets/ui/tokens.rcss` and checks every token appears in the generated file with the same value, plus four utility classes.

## Dependencies
- CMake targets linked by `sim_tests` (all PRIVATE): `dc::sim`, `dc::content`, `dc::game_session`, `Catch2::Catch2WithMain`, `dc_warnings`. `dc::platform` is not linked.
- Third party: Catch2 3 (`find_package(Catch2 3 CONFIG REQUIRED)`, headers `catch2/catch_test_macros.hpp`). nlohmann-json is not used directly; it is a private dependency of `game_session`.
- Headers included from other subsystems: `sim/*.h` (27 of the 30 public headers; not `controller.h`, `fatal.h` or `tech.h`), `content/loader.h`, `game/session.h`, `game/format.h`, `game/trace.h`, `game/replay.h`, `game/png.h`.
- Repository files read at run time through the baked-in paths: `data/` (all eight files: `resources`, `techs`, `regions`, `events`, `balance`, `ai`, `program` and `strings` JSON), `sim/src/view.cpp`, `docs/design/tokens.css`, `game/assets/ui/tokens.rcss`, `tools/prose/draft.tsv`.
- Included from the root `CMakeLists.txt` only when `DC_BUILD_TESTS` is ON (the default), after `enable_testing()`.

## Patterns
- Catch2 v3 with `Catch2WithMain`; there is no `main.cpp`. `catch_discover_tests(sim_tests)` makes each `TEST_CASE` its own CTest entry.
- Flat layout, one `<module>_test.cpp` per module under test, file-local helpers in anonymous namespaces (for example `firstListed`, `buyFirstListed`, `tickToNextMonthEnd`, `calmContent`, `certainEventContent`, `makeStageReady`, `giveRaceOrders`).
- Tags name the module and cross-cutting concern: `[ai]`, `[archive]`, `[content]`, `[data]`, `[design]`, `[determinism]`, `[ending]`, `[events]`, `[finance]`, `[fixed]`, `[format]`, `[ids]`, `[market]` (land auctions), `[markets]` (ore prices), `[math]`, `[mines]`, `[money]`, `[open]`, `[opening]`, `[pending]`, `[playtest4]`, `[png]`, `[program]`, `[random]`, `[replay]`, `[research]`, `[rng]`, `[save]`, `[sell_policy]`, `[session]`, `[spec008]`, `[spec010]`, `[stage-days]`, `[strings]`, `[surveys]`, `[trace]`, `[view]`, `[worldgen]`.
- Two content sources kept apart: the in-code fixture (`test_content.h`) for rule tests, and the shipped `data/` directory for `[data]` tests. Tests that tune a rule copy the fixture and edit one field.
- Save validation is tested by saving, corrupting state or bytes, and asserting the load is refused.
- Statistical tests loop over seeds 1..200 (`worldgen_test.cpp`, `data_files_test.cpp`); `ai_test.cpp` plays twenty simulated years.
- Session and trace tests use in-memory streams (`std::ostringstream`) and byte vectors, not temporary files.
- Source-text guard tests (`view_source_test.cpp`, `design_tokens_test.cpp`, the draft parity case in `strings_test.cpp`) assert on file contents with string search and `std::regex`.

## Constraints
- The three golden hashes in `determinism_test.cpp` use seed 42 and fixture content: `kGolden` = `0x059a7c79213dd307` (one year, no orders), `kGoldenPlayed` = `0x41192679894c4afc` (three years, AI orders for both companies) and `kGoldenRace` = `0xae14b05ab3e56760` (the scripted race to a founding). They are recorded on Linux/GCC and verified on Windows/MSVC in CI (`kGoldenRace` is confirmed for Windows only when CI runs). A deliberate change to sim state or rules updates the constant in the same commit; the comments on `kGoldenPlayed` and `kGoldenRace` require the reason to be recorded in `docs/DESIGN.md`, and each comment keeps the history of earlier values.
- `test_content.h` must stay independent of `data/*.json` so balance tuning does not move the golden hashes.
- `DC_DATA_DIR` and `DC_SOURCE_DIR` are absolute paths compiled in from `CMAKE_SOURCE_DIR`; the binary depends on the source tree being present at that path, not on the working directory.
- `test::fixtureStrings` relies on `data/strings.json` having one key per line, which `tools/prose/to_json.py` produces.
- `design_tokens_test.cpp` requires more than 40 tokens in `docs/design/tokens.css` and the `GENERATED by tools/design/tokens_to_rcss.py` marker in `tokens.rcss`.
- No test is hidden, skipped, marked may-fail or conditionally compiled; every case runs in every configuration that builds tests.
- Compiled with the project warning set (`dc_warnings`; presets set `DC_WARNINGS_AS_ERRORS=ON`).
- The `runner_smoke`, `runner_outcome`, `runner_sweep` and `runner_bite_measures` CTest entries are defined in `sim_runner/CMakeLists.txt`, and `layout_probe` in `game/CMakeLists.txt`, not here.
