# ui

**Purpose:** The RmlUi document, stylesheets and icon sheet that make up the client's single screen (plate C "Control Room", dashboard H4, as described in `docs/design/handoff.md`). All game text and numbers arrive through RmlUi data binding; nothing here contains game rules.

## Key Components
- `main.rml` - The one document. `<body data-model="game">` holds `#header` (company, date, cash, spendable, debt, cash sparkline, speed buttons, Stops/Save/Load/New game, the `#pausemenu` auto-pause checklist), `#strip` (month net, storage, mines, world event), `#body` with the `#rail` icon tabs and `#content`, `#status` and the game-over `#overlay`. `#content` switches on `tab`: 0 dashboard, 1 plots, 2 market, 3 research, 4 finance, 5 log. Uses the custom `<price-chart>` element.
- `main.rcss` - Hand-written stylesheet linked from `main.rml`. Declares the `@spritesheet icons` over `icons.tga` (six 24x24 cells), all layout and colour rules with literal token values, and the `body.deck` overrides for Steam Deck sizes.
- `tokens.rcss` - GENERATED by `tools/design/tokens_to_rcss.py` from `docs/design/tokens.css` (stated in its header comment). A comment table of every design token plus utility classes (`.c-*`, `.bg-*`, `.f-*`, `.fs-*`). Not linked from `main.rml`; it is the lookup table for the literal values in `main.rcss`.
- `icons.tga` - Binary. The rail's icon sprite sheet; per the docstring of `tools/design/icons.py` it is generated by that script (six 24x24 white-on-transparent line icons in a row, uncompressed TGA).

## Dependencies
- Data model "game" and its event callbacks (`set_speed`, `step`, `toggle_pause_menu`, `toggle_pause`, `need_action`, `toggle_mine`, `bid`, `survey`, `build`, `sell`, `sell_all`, `research`, `repay`, `repay_all`, `take_loan`, `save`, `load`, `new_game`, ...) are bound in `App::bindModel` in `game/src/app.cpp`; bound fields are the members of `UiModel` in `game/src/ui_model.h`.
- `<price-chart>` is implemented by `PriceChartElement` in `game/src/chart_element.cpp`.
- Font families come from `game/assets/fonts/`.
- Sentences are bound from the prose catalogue `data/strings.json` through the model; the RML comment states only one- or two-word labels are literal.
- `tests/design_tokens_test.cpp` reads `tokens.rcss` and compares it with `docs/design/tokens.css`.
- `main.rml` is loaded by `App::loadDocument` as `<assetsDir>/ui/main.rml`.

## Patterns
- RmlUi RML/RCSS with data binding: `{{var}}`, `data-if`, `data-for`, `data-class-*`, `data-value`, `data-event-click`.
- RmlUi has no default stylesheet and no custom properties, so every rule is explicit and token values are written as literals; units are `dp`.
- Responsive variant by a `deck` class on `<body>` (set by the app below 1300dp window width or with `--deck`); buttons carry `.long`/`.short` label spans swapped by that class.
- Generated artefacts are committed, not built by CMake.

## Constraints
- `tokens.rcss` carries a "Do not edit" header: tokens are changed in `docs/design/tokens.css` and the file regenerated.
- The `@spritesheet` cell rectangles in `main.rcss` must match the 144x24 layout of `icons.tga` (the layout probe's stub renderer reports that size).
- Every variable and event name used in `main.rml` must be bound in `App::bindModel`; the `layout_probe` test fails on any RmlUi warning such as an unbound variable or unknown RCSS property.
- In the deck frame no text may fall below 14dp (checked by `layout_probe`).
