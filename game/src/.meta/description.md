# src (game client)

**Purpose:** Source of the playable client `deep_claim` and of the headless `deep_claim_layout_probe`. It hosts an RmlUi context, turns a `game::Session` into bindable strings, and turns interface events into `sim::Command`s; it contains no game rules.

## Key Components
- `main.cpp` - Entry point of `deep_claim`. Parses `--deck`; locates `data/` and `assets/` next to the executable (`SDL_GetBasePath`) or falls back to `DC_DATA_DIR`/`DC_ASSETS_DIR`; loads content with `content::loadFromDirectory` before opening the window; `Backend::Initialize("Deep Claim", 1366, 820, true)`; loads the seven font faces; registers `<price-chart>`; builds `platform::makeNullServices` on `SDL_GetPrefPath("DeepClaim", "DeepClaim")`; resolves the playtest directory (`DEEP_CLAIM_PLAYTEST` env var, else `DC_PLAYTEST_DIR`, else `<prefPath>/playtest`); passes `DC_BUILD_ID` from the generated header `dc_build_id.h` to `App`; runs the frame loop. `keyDown` routes F8 to the RmlUi debugger and F9/F12 and unconsumed keys to `App::onKey`; `preSwap` services screenshot requests.
- `app.h` / `app.cpp` - `class App`: owns the `Session`, the `UiModel`, the RmlUi data model "game" and the document. Seven tabs (`kTabNames`: dashboard, plots, market, research, finance, log, program). `bindModel` registers every struct, variable and event callback used by `main.rml`. `update` advances the session, writes the trace's end record the moment the game is over (`traceEnd`), shows the auto-pause reason, expires the status line after 6 s, toggles the deck class below 1300dp and refreshes on a new day. The `on*` handlers parse the text inputs with `parseMoney`/`parseTonnes` and give every order through `App::order`, which queues it with `Session::submit` and redraws at once (false once the game is over). Program tab handlers `onDeliver`, `onProgramResearch`, `onCompleteStage`; pending-order handlers `onCancel`, `onCancelAll`; `showPopover` keeps at most one of the auto-pause menu and the waiting-orders list open. Clock controls and orders are ignored once the game is over. Also: save/load of `autosave.dcsave` (written to `.tmp` then renamed), auto-pause rules in `autopause.txt`, the playtest trace (`trace-YYYYMMDD-HHMMSS.jsonl`, save copies, up to 200 screenshots), keyboard shortcuts (space, 1/2/3, period, F9, F12), and public hooks used only by the layout probe (`setTab`, `startGame`, `selectPlot`, `showPauseMenu`, `showPendingList`, `setLogFilter`, `refreshNow`, `session`).
- `ui_model.h` / `ui_model.cpp` - `struct UiModel` and its row structs (`OrderMark`, `PendingRow`, `NeedRow`, `SaleRow`, `SoldRow`, `MineFigures`, `OwnedRow`, `EstimateRow`, `PlotPanel`, `ResourceRow`, `TechRow`, `LoanRow`, `LogRow`, `PauseRow`, `RaceRow`, `ProgramStageRow`, `ProgramNeedRow`, `ProgramPanel`, `EndStageLine`, `EndCompany`, `EndPanel`): flat, pre-formatted strings and flags. `OrderMark` is the pending chip (text, order id, not-covered flag) carried by every control that can give an order; `MineFigures` is a mine's daily margin, loss and break-even price (spec 008). `refreshModel(session, model)` reads the pending orders once (`readOrders`) and rebuilds everything through file-local `fill*` functions, in order `fillPending`, `fillStrip`, `fillRace`, `fillNeeds`, `fillOwned`, `fillFinanceRow`, `fillSale`, `fillPanel`, `fillResources`, `fillTechs`, `fillFinance`, `fillProgram`, `fillLog`, `fillPauseRows`, `fillEnd` (`fillRecentSales` is called from within).
- `chart_element.h` / `chart_element.cpp` - `PriceChartElement`, the custom RmlUi element `<price-chart resource days mode series>` drawn with `Rml::Geometry` (line sparkline with area, dashed baseline and endpoint mark, or absolute columns). Data comes from static `ChartProvider`/`CashProvider` callbacks installed by `App`; `registerChartElement` installs the instancer.
- `screenshot.h` / `screenshot.cpp` - `captureFramebufferPng`: `glReadPixels` of the back buffer, row flip, `game::encodePngRgb`, write to file. Compiled into `deep_claim` only.
- `layout_probe.cpp` - Entry point of `deep_claim_layout_probe`, registered as CTest `layout_probe`. Runs the real `App` and `main.rml` with a stub `Rml::RenderInterface` and a logging `Rml::SystemInterface`, lays out all seven tabs at 1366x820 and 1280x800 on a fresh game and on fixed-seed scripted games (`kScenarioSeed` = 20261009), and exits non-zero on layout faults, RmlUi warnings, scenario failures or a missing trace header. Later passes click the real buttons and compare what is on screen with the sim's view: pending orders (spec 007), a losing mine with the stop rule on and off (spec 008), the race strip, the Program tab, the Stops menu, exact prices and the end screen for each ending (founded, lesser partner, lost, deadline, bankrupt; spec 010). Passes that need altered balance build their own copy of the content and run on an app and RmlUi context of their own (`onItsOwnApp`). Each pass has its own exit code (`kLayoutFailure` 3, `kScenarioFailure` 5, `kPendingFailure` 6, `kLosingFailure` 7, `kRaceFailure` 8, `kUncaught` 9, `kProgramFailure` 10, `kEndFailure` 11, `kStopsFailure` 12, `kPricesFailure` 13).

## Patterns
- View-model: `UiModel` is a snapshot rebuilt from `Session::view()` and `Session::pendingOrders()` on each refresh, followed by `DirtyAllVariables`; the RML never touches sim types.
- Pending orders are shown in place: each order control swaps for a chip and Cancel while its order waits, and the header's waiting line opens the full list.
- RmlUi data binding with `BindEventCallback` lambdas that forward to `App::on*` member functions.
- Global function-pointer bridge: the backend callbacks are plain function pointers, so `main.cpp` reaches the app through a file-static `gApp`.
- Provider callbacks decouple the chart element from the session type.
- Screenshots are a request/acknowledge handshake: `App` queues a path, the host captures in the pre-swap callback and calls `screenshotDone`.
- All player-visible sentences come from `game::text(content, key, ...)`; C++ holds keys, not prose.
- `NOLINT` comments with a reason where clang-tidy checks are suppressed.

## Constraints
- No game rules here (stated in `game/CMakeLists.txt`); state changes only through `Session::submit`/`cancel`, `Session::load` and new games. Figures such as Committed, Available and a mine's break-even are read from the session and view, not computed against sim rules (R-001).
- `deep_claim_layout_probe` compiles `app.cpp`, `ui_model.cpp` and `chart_element.cpp` without SDL or the backend, so those three files must not include SDL or GL headers.
- `kDeckWidth` (1300) is defined separately in `app.cpp` and `layout_probe.cpp`; the font list is duplicated in `main.cpp` and `layout_probe.cpp`.
- `App` is non-copyable and non-movable; it must be destroyed before `Rml::Shutdown`.
- A new game uses a clock-derived seed and one AI rival named "Northfield Minerals".
- The trace is optional: an empty playtest directory disables trace, save copies and screenshots.
- Large files: `layout_probe.cpp` 3858 lines, `ui_model.cpp` 2067, `app.cpp` 1365, `ui_model.h` 527; `App::bindModel` is about 500 lines.
